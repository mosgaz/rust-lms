# AGENTS.md — Инструкции для AI-агентов

Этот файл — первичная точка входа для любого AI-агента (Claude Code, Cursor, Cline, Codex, Copilot), работающего с репозиторием `rust-lms`.

Общая навигация по документации — в [`specs/README.md`](README.md).

## 🚦 Перед выполнением ЛЮБОЙ задачи

Выполняй эти шаги строго по порядку:

1. Прочитай `specs/SPECIFICATION.md` — это главный источник истины для бизнес-требований.
2. Прочитай `specs/STRUCTURE.md` — пойми физическую структуру каталогов проекта, правила направленности зависимостей и Cargo workspace.
3. Прочитай стандарты коммитов и ветвления `/CONTRIBUTING.md`. Мы строго придерживаемся спецификации Conventional Commits для автоматической генерации семантического версионирования и формирования `CHANGELOG.md`. Каждый коммит должен соответствовать шаблону: `категория(область): описание`.
4. Прочитай технические спецификации, относящиеся к твоей задаче:
   - Если меняешь структуру БД или логику аналитики LRS — изучи `specs/DB_SCHEMA.md` и `specs/MIGRATIONS.md`.
   - Если разрабатываешь или правишь эндпоинты, токены и вебхуки — изучи `specs/OPEN_API.md`.
   - Если работаешь над PWA, Service Worker или очередями IndexedDB — изучи `specs/OFFLINE_SYNC.md`.
   - Если вносишь изменения в рантайм плагинов или SDK — изучи `specs/PLUGIN.md` и шаблон `specs/PLUGIN_DEVELOPMENT_TEMPLATE.md`.
   - Если правишь конфигурацию контейнеров, сетевые шлюзы или CSP — изучи `specs/DEPLOY.md`.
   - Если задача затрагивает роли, доступы или логирование — изучи `specs/RBAC.md` и `specs/DIAGNOSTICS.md`.
   - Если задача затрагивает стандарты (SCORM, xAPI, LTI), доступность (WCAG) или compliance (GDPR/CCPA) — изучи `specs/STANDARDS.md`.
   - Если задача касается чатов, комментариев или уведомлений — изучи `specs/COMMUNICATIONS.md`.
   - Если задача касается ВКС — изучи `specs/CONFERENCING.md`.
5. Прочитай `specs/CODING_STANDARDS.md` — следуй правилам full-stack Rust буквально. Это закон, а не рекомендация.
6. Определи ответственность — если задача выходит за рамки текущего крейта или нарушает изоляцию тенантов, остановись и спроси.
7. Проверь dependency rules (§4 `specs/STRUCTURE.md`) — твой код не должен нарушать направления зависимостей.
8. Напиши тесты — для любой новой публичной функции, эндпоинта Open API или контракта SDK. Без тестов задача не считается выполненной.
9. Запусти локальные проверки перед коммитом:
   ```bash
   cargo clippy --all-targets --all-features -- -D warnings
   cargo fmt --all -- --check
   cargo test --workspace
