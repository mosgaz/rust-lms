## ✅ Завершённые этапы (1-9)

### Этап 1: Инициализация проекта
**Статус:** ✅ Завершён  
**Коммит:** `build(workspace): configure monorepo structure and Leptos 0.8 integration`  
**Описание:** Настройка монорепозитория и базовой инфраструктуры проекта.  
**Что реализовано:**
- Cargo workspace с семью крейтами (shared, ui, icons, api, client, server, cli)
- Переименование крейтов с префиксом `rust-lms-` для предотвращения коллизий зависимостей
- Интеграция Leptos 0.8 с Axum 0.8 и tower-http 0.6
- Настройка `resolver = "2"` и фичи `js` для `uuid` под WASM-таргет
- Конфигурация `cargo-leptos` для корректной сборки клиентского бандла
- Фасадный паттерн в клиентском крейте для развязки внутренних импортов
- Базовые компонентные заглушки в UI-крейте
- Docker Compose для локальной разработки
- Базовая структура директорий и конфигурационных файлов  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 2: Идентификация и аутентификация
**Статус:** ✅ Завершён  
**Описание:** Базовая система аутентификации с криптографическим хешированием паролей и JWT-токенами.  
**Что реализовано:**
- Хеширование паролей по алгоритму Argon2id (RFC 9106, PHC-формат)
- Менеджер JWT с генерацией и валидацией токенов
- Три типа токенов: Access, Refresh, Session
- Конфигурация через переменные окружения с префиксом `RUST_LMS_JWT_*`
- Middleware для извлечения и валидации Bearer-токенов
- REST-эндпоинты для логина и обновления токенов
- Модульные тесты (5 штук)  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 3: Identity-First архитектура
**Статус:** ✅ Завершён  
**Документация:** ADR `2026.10.05-0011`  
**Описание:** Разделение глобальной личности и ролей в тенантах. Одна личность может иметь доступ к нескольким организациям.  
**Что реализовано:**
- Таблица `identities` (глобальная личность: email, password_hash, preferred_tenant_id)
- Таблица `users` (связь личности с тенантом: identity_id, tenant_id, is_active)
- Двухшаговая аутентификация (Логин → Выбор тенанта → Финальные токены)
- Автовыбор тенанта через поле `preferred_tenant_id`
- Сервис аутентификации с методами для двухшагового потока
- Миграция `20261003000001_init_rls_and_tenants.sql`  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 4: Multi-tenancy и RLS
**Статус:** ✅ Завершён  
**Документация:** ADR `2026.09.28-0001`  
**Описание:** Строгая изоляция данных между организациями на уровне СУБД через Row-Level Security.  
**Что реализовано:**
- Активация RLS на всех таблицах с данными тенантов
- Политики изоляции через сессионную переменную `app.current_tenant_id`
- RLS-контекст в транзакциях через `SET LOCAL`
- Middleware для инжекции идентификатора тенанта из JWT в контекст запроса  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 5: Content Hierarchy (Courses + Nodes)
**Статус:** ✅ Завершён  
**Описание:** Иерархическая структура учебного контента с поддержкой гибкой вложенности.  
**Что реализовано:**
- Таблицы `courses` и `nodes` (универсальная сущность для глав, тем и уроков)
- Расширение PostgreSQL `ltree` для иерархических запросов
- GiST/GIN индексы для быстрого поиска поддеревьев
- Репозитории для курсов и узлов с операциями перемещения и пересчёта путей
- Миграция `20261006000001_create_content_hierarchy.sql`
- 14 REST-эндпоинтов для управления контентом  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 6: API Layer (REST handlers)
**Статус:** ✅ Завершён  
**Описание:** HTTP-слой на базе Axum с унифицированным форматом ответов.  
**Что реализовано:**
- Сборка Axum-роутера с разделением на публичные и защищённые маршруты
- Унифицированный формат ответа с полями «успех», «данные», «ошибка»
- Обработка ошибок с маппингом в HTTP-статусы
- Точка входа сервера с инициализацией трейсинга, конфигурации и graceful shutdown  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 7: Course Enrollments (Self-paced)
**Статус:** ✅ Завершён  
**Описание:** Индивидуальные зачисления пользователей на курсы вне потоков.  
**Что реализовано:**
- Таблица `course_enrollments` с полями статуса и прогресса
- Защита от дублирующего зачисления (409 Conflict)
- Мягкое удаление через статус `dropped` с сохранением истории
- 4 REST-эндпоинта для управления зачислениями  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 8: Batches & Enrollments
**Статус:** ✅ Завершён  
**Описание:** Когортное обучение — потоки студентов с фиксированным расписанием.  
**Что реализовано:**
- Таблицы `batches`, `batch_courses`, `batch_enrollments`
- Четыре роли участников: студент, инструктор, тьютор, наблюдатель
- Жизненный цикл потока: черновик, активный, архивированный, завершённый
- 12 REST-эндпоинтов для управления потоками
- Миграция `20261007000001_create_batches_and_enrollments.sql`  
**Критерии готовности:** Все интеграционные тесты проходят.

### Этап 9: Progress Tracking & Completion
**Статус:** ✅ Завершён  
**Описание:** Отслеживание прогресса студентов по урокам и автоматическое завершение курсов.  
**Что реализовано:**
- Таблица `lesson_progress` с полями статуса, балла, времени и попыток
- Инкрементальный пересчёт прогресса через денормализованное поле веса завершённых уроков
- Четыре типа критериев завершения и режимы проверки (AllOf/AnyOf)
- Транзакционная защита от гонки через блокировку строк
- Денормализация общего веса курса через триггер
- Миграции `20261008000001` и `20261009000001`  
**Критерии готовности:** Все интеграционные тесты проходят.

## 🔴 Фаза 1: Ядро MVP (Этапы 10-12)

### Этап 10: Assessments Engine
**Приоритет:** 🔴 P0 | **Статус:** 🔴 Не начат | **Зависимости:** Этап 9  
**Документация:** `specs/SPECIFICATION.md` §3  
**Описание:** Реализация системы тестирования: модели вопросов и ответов, прохождение тестов, подсчёт баллов, интеграция с прогрессом обучения.  
**Подэтапы:**
- **10.1. Модели данных:** Вопрос (тип, варианты, вес, объяснение), Попытка (статус, время, балл), Ответ (связь попытки с вопросом, признак правильности).
- **10.2. Миграция базы данных:** Создание таблиц, RLS-политики, индексы, CHECK-констрейнты.
- **10.3. Репозиторий вопросов:** CRUD, получение списка, изменение порядка.
- **10.4. Репозиторий попыток:** Начало попытки, сохранение ответа, завершение с подсчётом, история.
- **10.5. Движок подсчёта баллов:** Логика сравнения ответов, подсчёт суммарного балла, определение сдачи по порогу.
- **10.6. REST API:** Эндпоинты для списка вопросов, начала попытки, отправки ответа, завершения, истории и деталей.
- **10.7. Интеграция с прогрессом:** Автоматическое обновление прогресса урока при успешном завершении попытки.
- **10.8. Интеграционные тесты:** Сценарии создания тестов, прохождения, подсчёта баллов и интеграции с прогрессом.  
**Критерии готовности:**
- Можно создать тест с вопросами разных типов
- Студент может начать попытку и отвечать на вопросы
- Система корректно подсчитывает баллы и отмечает урок как завершённый при успехе
- История попыток сохраняется и доступна
- Все интеграционные тесты проходят

### Этап 11: Certification Engine (MVP)
**Приоритет:** 🔴 P0 | **Статус:** 🔴 Не начат | **Зависимости:** Этап 10  
**Документация:** `specs/SPECIFICATION.md` §4  
**Описание:** Автоматическая выдача сертификатов при завершении курса, генерация PDF, публичная верификация.  
**Подэтапы:**
- **11.1. Репозиторий сертификатов:** Выдача при завершении курса, генерация уникального верификационного хеша.
- **11.2. Генерация PDF:** Шаблон с данными студента, курса, даты и кода верификации.
- **11.3. Отправка уведомлений:** Отправка письма с PDF-вложением через SMTP.
- **11.4. REST API:** Список сертификатов, скачивание PDF, публичная страница верификации по коду.
- **11.5. Интеграция с завершением курса:** Триггер при изменении статуса зачисления на «завершён».
- **11.6. Интеграционные тесты:** Сценарии выдачи, скачивания, верификации и отправки письма.  
**Критерии готовности:**
- Сертификат выдаётся автоматически при завершении курса
- PDF содержит корректные данные, письмо доставляется
- Публичная страница верификации работает без аутентификации
- Все интеграционные тесты проходят

### Этап 12: Minimal Frontend
**Приоритет:** 🔴 P0 | **Статус:** 🔴 Не начат | **Зависимости:** Этапы 10-11  
**Описание:** Базовый веб-интерфейс для студентов: личный кабинет, каталог, просмотр уроков, тесты, сертификаты.  
**Подэтапы:**
- **12.1. Роутинг и навигация:** Структура путей, общий макет с меню.

- Личный кабинет и каталог курсов работают корректно
- Можно открыть урок, пройти тест и получить результат
- Можно скачать сертификат
- Интерфейс адаптивен для десктопа и мобильных устройств
- Интерфейс полностью локализован, поддерживается переключение языка и RTL
- Все интеграционные тесты проходят
