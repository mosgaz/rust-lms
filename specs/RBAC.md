# Ролевая модель и разграничение доступов (RBAC Matrix)

Авторизация выполняется через SSO на уровне тенанта. Метаданные пользователя маппятся в одну из системных ролей внутри таблицы `users` (см. [`DB_SCHEMA.md`](DB_SCHEMA.md) §1.2). Роли и их scopes фиксируются на уровне тенанта при генерации API-ключей (см. [`OPEN_API.md`](OPEN_API.md) §2).

## Роли и scopes

| Системная роль | Описание и Границы ответственности в рамках тенанта | Scopes в API |
|:---|:---|:---|
| **Глобальный Администратор** | *(Вне RLS)* Управляет созданием тенантов через Глобальный API Ключ. | `infrastructure:provisioning`, `infrastructure:monitor` |
| **Администратор Тенанта** | Полный контроль внутри организации. Управляет Open API токенами тенанта. Настраивает SCIM-интеграцию с HRIS/HRM. | `*:*` в рамках RLS (включая `scim:sync`) |
| **Инструктор (Преподаватель)** | Создает курсы/юниты, настраивает пулы вопросов тестов (`Quizzes`). Публикует новые версии контента. | `courses:*`, `quizzes:*`, `assignments:evaluate` |
| **Ментор (Проверяющий)** | Закреплен за конкретными потоками (`Batches`). Проверяет практические работы. | `assignments:evaluate` |
| **Обучающийся (Learner)** | Доступ к прохождению контента, тестов, WASM-плагинов и получению сертификатов. Работает через PWA-клиент. | `content:read`, `analytics:write`, `certificates:read` |
| **Наблюдатель (Observer)** | Чтение аналитики успеваемости без права изменения контента или прохождения. | `analytics:read` |

## Примечания

* **`infrastructure:*`** — только для глобального администратора; не привязано ни к какому `tenant_id` (работает вне RLS).
* **`*:*` в рамках RLS** — администратор тенанта имеет полный набор прав, но каждое действие ограничено политикой RLS (`app.current_tenant_id`). Выход за пределы тенанта технически невозможен. `scim:sync` входит в `*:*` как отдельный функциональный scope для SCIM-интеграции.
* **`scim:sync`** — выдаётся администратору тенанта для настройки SCIM 2.0-интеграции с внешними HRIS/HRM (Workday, SAP SuccessFactors, 1C:ЗУП). Используется эндпоинтами `/scim/v2/Users` и `/scim/v2/Groups` (см. [`OPEN_API.md`](OPEN_API.md) §3.5 и [`STANDARDS.md`](STANDARDS.md) §«SCIM 2.0»). Обычно выделяется в отдельный API-ключ для HRIS-системы, чтобы не выдавать ей полный `*:*`.
* **`content:read`** — доступ к структуре программ, курсов, юнитов и контенту, к которому пользователь зачислен. Включает право на выдачу подписанных URL для медиа (`POST /api/v1/content/signed-url`, см. [`OPEN_API.md`](OPEN_API.md) §3.6). Если для медиа настроен DRM, `content:read` даёт право на получение DRM-лицензии в рамках активной сессии.
* **`analytics:write`** — выдаётся роли «Обучающийся» для вызова `POST /api/v1/analytics/lrs/sync` — пакетной синхронизации offline-очереди PWA (см. [`OPEN_API.md`](OPEN_API.md) §3.4 и [`OFFLINE_SYNC.md`](OFFLINE_SYNC.md) §4).
* **`analytics:read`** — чтение аналитики успеваемости; также право на экспорт LRS (`GET /api/v1/analytics/lrs/statements`, см. [`OPEN_API.md`](OPEN_API.md) §3.3).
* **`courses:*`, `quizzes:*`** — полный набор операций с курсами и тестами в рамках тенанта: создание, редактирование, публикация новой версии (`courses.version` / `course_versions`), архивация.
* **`assignments:evaluate`** — право выставлять оценки по практическим заданиям. Доступно инструктору и ментору; ментор ограничен закреплёнными за ним потоками (`Batches`).
* **`certificates:read`** — доступ к реестру собственных сертификатов и публичной верификации по `verification_hash`.
* **`certificates:verify`** — публичная верификация сертификатов по `verification_hash` (используется внешними системами и публичной страницей верификации; не требует аутентификации пользователя в тенанте).
