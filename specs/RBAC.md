# Ролевая модель и разграничение доступов (RBAC Matrix)

Авторизация выполняется через SSO на уровне тенанта. Метаданные пользователя маппятся в одну из системных ролей внутри таблицы `users` (см. `DB_SCHEMA.md`).

| Системная роль | Описание и Границы ответственности в рамках тенанта | Scopes в API |
|:---|:---|:---|
| **Глобальный Администратор** | *(Вне RLS)* Управляет созданием тенантов через Глобальный API Ключ. | `infrastructure:*` |
| **Администратор Тенанта** | Полный контроль внутри организации. Управляет Open API токенами тенанта. | `*:*` в рамках RLS |
| **Инструктор (Преподаватель)**| Создает курсы/юниты, настраивает пулы вопросов тестов (`Quizzes`). | `courses:*`, `quizzes:*` |
| **Ментор (Проверяющий)** | Закреплен за конкретными потоками (`Batches`). Проверяет практические работы. | `assignments:evaluate` |
| **Обучающийся (Learner)** | Доступ к прохождению контента, тестов, WASM-плагинов и получению сертификатов.| Локальный PWA-токен |
| **Наблюдатель (Observer)** | Чтение аналитики успеваемости без права изменения контента или прохождения.| `analytics:read` |
