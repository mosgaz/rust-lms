## Спецификация Технического Задания: Структура Проекта
Файл спецификации: specs/STRUCTURE.md
## 1. Концепция Workspace-архитектуры
Проект спроектирован по принципу микро-крейтов (micro-crates) в рамках единого монорепозитория (Cargo workspace). Каждая папка внутри каталога crates/ решает строго изолированную задачу рантайма.
Это предотвращает циклическое связывание модулей и исключает риск утечки нативного серверного кода (сетевые сокеты, файловые дескрипторы ОС) в клиентский WebAssembly-бандл, что привело бы к невозможности сборки PWA.

## 3. Детализация внутренней структуры крейтов## 3.1. Крейт: crates/shared (DTO & Contracts)
Абсолютно плоский крейт без привязки к СУБД или UI. Содержит структуры данных, компилируемые как под wasm32, так и под нативный x86_64/arm64 сервер.

* src/models/ — структуры сущностей (User, Course, Program, Batch, Certificate).
* src/dto/ — запросы и ответы API-интерфейсов (ImportPayload, SyncPackage).
* src/xapi/ — строгие иммутабельные типы для генерации xAPI Statements.

## 3.2. Крейт: crates/ui (Shared UI Library)
Изолированная дизайн-система платформы. Содержит переиспользуемые Leptos-компоненты хоста (формы, списки, кнопки, диалоги, тостеры уведомлений Fluent-локализации), не привязанные к конкретным роутам страниц. Должна компилироваться в WASM-контур.
## 3.3. Крейт: crates/api (Business Logic & Data Layer)
Серверное бэкенд-ядро обработки данных. Импорт макросов Leptos сюда аппаратно запрещен.

* src/database/ — менеджер пула соединений SQLx, миграции и RLS-интерцептор (SET LOCAL app.current_tenant_id).
* src/lrs/ — низкоуровневая обработка записей LRS (пакетный импорт в TimescaleDB или ClickHouse).
* src/etl/ — потоковые чанк-парсеры кастомного импорта пользователей (Custom ETL Mapper).

## 3.4. Крейт: crates/admin (Admin App)
Изоморфное Leptos-приложение панели управления организацией. Использует crates/shared и crates/ui.

* src/components/ & src/pages/ — интерфейсы распределения батчей, создания программ, выдачи токенов Open API и кастомизации White Labeling.
* src/server.rs — реализация #[server] RPC-функций админки, которые внутри транзакционно обращаются к методам crates/api.

## 3.5. Крейт: crates/client (Client PWA & Plugin Host)
Изоморфное Leptos-приложение обучающегося. Компилируется в PWA.

* src/pages/ — личный кабинет студента, плеер юнитов, интерфейсы прохождения Quizzes и ручной сдачи Assignments.
* src/pwa/ & src/storage/ — Service Worker, кэш-стратегии медиа и IndexedDB автономная очередь логов (OFFLINE_SYNC.md).
* src/plugins/ — Plugin SDK (WASM-биндинги и postMessage-мосты рантайма плагинов).
* src/server.rs — #[server] RPC-функции для синхронизации офлайн-пакетов LRS и верификации сертификатов.

## 3.6. Крейт: crates/server (Axum Runtime Host)
Чисто серверное приложение. Единственная точка входа, содержащая функцию fn main().

* Считывает инфраструктурную конфигурацию config.toml.
* Инициализирует пулы подключений SQLx к PostgreSQL и ClickHouse.
* Монтирует Axum-роутер, связывает его с #[server] RPC-эндпоинтами крейтов admin и client, регистрирует REST-эндпоинты Open API (OPEN_API.md) и запускает Tokio рантайм.

## 4. Направленность зависимостей и правила изоляции (Dependency Rules)

       [ crates/server ] (Axum Main Host)
         │           │
         ▼           ▼
   [ crates/admin ] [ crates/client ]  (Leptos Apps + #[server] RPC)
         │     │       │     │
         │     └─┐   ┌─┘     │
         ▼       ▼   ▼       ▼
   [ crates/api ] [ crates/ui ]        (Data Layer / Shared UI KIT)
         │               │
         └───────┬───────┘
                 ▼
         [ crates/shared ]            (Flat DTOs & xAPI Schemas)


   1. Запрет обратного импорта: Крейт shared не знает ничего о существовании верхних слоев. Крейт api никогда не зависит от Leptos-приложений admin или client.
   2. Изоляция WASM-контура: Крейты ui, admin и client компилируются под таргет wasm32-unknown-unknown для работы в браузере. Им запрещено напрямую использовать crates/api или crates/server. Вся связь между фронтенд-компонентами и бэкенд-логикой идет строго через объявления Leptos #[server] RPC-функций или асинхронные вызовы сетевого Open API.
   3. Идемпотентность типов: Общие структуры в shared должны использовать примитивы, одинаково сериализуемые как макросами serde, так и serde_wasm_bindgen.
